# Разработка и проверка на телефоне

Приложение называется **Personal Throughput Accounting**. Переименование в версии 0.7.5 сохраняет идентификатор пакета и ключ подписи, поэтому устанавливается как обычное обновление с прежними данными и разрешениями.

Исходники: https://github.com/malikvalikhodjaev/finance-accountier. Разработка и установка выполняются на этом компьютере; GitHub хранит коммиты и теги. Компьютер и телефон должны быть в одной сети Wi-Fi, а на телефоне включена «Отладка по Wi-Fi». Для обновлений используется прежний пакет `uz.rhythm.money` и прежний ключ `.signing/local.jks`.

## Обычное обновление

После правок в папке `finance-collector` выполни:

```powershell
node release.mjs 0.3.1 --message "Исправления по проверке на телефоне"
```

Номер должен быть выше текущего. Скрипт проверяет подключение нужного телефона и обычный профиль, увеличивает `versionCode`, запускает тесты, проверяет сборку, сохраняет исходники в коммит и тег `v0.3.1`, собирает APK из сохранённого коммита, отправляет исходники и теги в `origin`, устанавливает обновление по Wi-Fi и открывает приложение. Сначала выполняется пробная компиляция, затем сборка с идентификатором окончательного коммита.

Внизу главного экрана видны версия и первые восемь символов коммита. При сообщении об ошибке укажи их, действие и получившийся результат. Для следующего выпуска выбери следующий номер версии.

Если процесс остановился после коммита, причина выводится в терминале. После её устранения продолжи ту же версию:

```powershell
node release.mjs 0.3.1 --resume
```

Повтор сохраняет версию и тег. Для установки уже собранного текущего коммита:

```powershell
node phone.mjs status
node phone.mjs install
```

По умолчанию используется только Wi-Fi. Кабель можно отключить после настройки. Скрипт проверяет аппаратный серийный номер телефона; на другое устройство обновление автоматически не отправляется.

## Первое подключение или смена компьютера

На Android 11 и новее открой «Для разработчиков → Отладка по Wi-Fi», включи переключатель и выбери подключение с помощью кода. В папке проекта:

```powershell
node bootstrap-tools.mjs
node bootstrap-adb.mjs
node phone.mjs pair
node phone.mjs connect
node phone.mjs status
```

`pair` спрашивает адрес, порт и одноразовый шестизначный код из окна сопряжения. `connect` спрашивает адрес и порт с основного экрана отладки: порт подключения отличается от порта сопряжения. Код не сохраняется. Если этот компьютер уже есть среди подключённых устройств, достаточно `connect`.

Адрес и серийный номер остаются локально в `.phone/device.json`. При смене порта скрипт ищет объявление того же телефона через mDNS; если сеть блокирует обнаружение, снова выполни `connect`. На этом компьютере сервер ADB использует порт 15037.

В обычном профиле Xiaomi установка может потребовать переключатель «Установка через USB» даже при работе с ADB по Wi-Fi. Если система выдаёт `INSTALL_FAILED_USER_RESTRICTED`, включи его и подтверди установку штатным диалогом, затем повтори установку. После сеанса верни переключатель в прежнее состояние. Отдельный «Режим отладки» Xiaomi создаёт другой профиль; в него приложение не устанавливается этим скриптом.

После нового клонирования восстанови **существующий** `.signing/local.jks` из своей отдельной копии. Потеря ключа препятствует обновлению уже установленного приложения. Новый ключ автоматически не создаётся. Для GitHub нужна авторизация Git с правом записи в этот репозиторий.

## Хранение версий и данных

- APK и описание сборки сохраняются локально в `output/`. Имя содержит версию, коммит и часть SHA-256; старые APK не перезаписываются. `latest-build.json` указывает на последнюю проверенную сборку.
- `.signing/`, `.phone/`, `.samples/`, инструменты, APK и личные тесты исключены из публичного Git. Первоначальные исходники и документация сохранены отдельно в `output/source-0.2.0-before-public-git.zip`.
- Обновление устанавливается через `adb install -r` без удаления приложения. Скрипт проверяет сохранность выданных разрешений SMS, вопросов и доступа к уведомлениям. Финансовые данные остаются в базе приложения на телефоне.
- Для исправления ошибочного выпуска создавай более высокую версию. Удаление приложения, очистка его данных и принудительное понижение версии в этот процесс не входят.

Для подготовки выпуска без телефона есть `--no-install`; для локального выпуска без отправки в GitHub — `--no-push`. В этих случаях скрипт явно сообщает, что соответствующий этап пропущен. Постоянного наблюдения за GitHub и фоновой установки нет: полный цикл запускается командой выпуска на компьютере.
