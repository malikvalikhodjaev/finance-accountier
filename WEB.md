# Общие таблицы и дашборды

Первая версия работает на личном компьютере в домашней сети. Открой `Open-Finance.cmd`: он запускает сервер в фоне и открывает http://127.0.0.1:8788. Телефон использует адрес из окна «Подключение». Компьютер должен быть включён, сервер запущен, а устройства — в одной сети. Доступ через интернет не настроен.

## Подключить приложение

На ПК нажми **Подключение → Получить код подключения**. В приложении **Ритм · деньги → Подключить общую таблицу** введи адрес с ПК и шестизначный код. Он действует 5 минут и используется один раз. После подключения доступны **Общая таблица операций**, **Мои дашборды** и **Синхронизировать сейчас**.

Сначала операция и её изменения сохраняются в SQLite на телефоне. После подключения передаются существующие операции, затем новые операции и ответы. Правки из веб-таблицы возвращаются на телефон. Исходные банковские тексты и идентификаторы сохраняются. Переводы, неясные операции и возможные повторы не превращаются в расходы.

После новых записей запрашивается фоновая синхронизация; периодическая задача проверяет изменения примерно раз в 15 минут. Android и ограничения батареи могут отложить выполнение. Без связи операции остаются на телефоне и ждут отправки. Сбор SMS и уведомлений не требует отладки Android.

Отладка по Wi-Fi нужна только для обновления APK. Обычная синхронизация использует HTTP с настроенным адресом в частной локальной сети; HTTPS также поддерживается. Эта конфигурация предназначена для домашней сети.

## Развивать таблицу

- **Своя колонка** добавляет текст, число, дату, выбор из списка или да/нет. Значения редактируются в карточке операции.
- **Колонки** выбирает видимые поля. **Настроить** у своей колонки меняет название, варианты и видимость. Скрытие сохраняет значения; тип существующей колонки сохраняется. Прежние значения из списка сохраняются даже после изменения вариантов.
- Фильтры: период, поиск, валюта, движение (поступление/списание), тип, учёт и категория. **Сохранить вид** сохраняет фильтры и колонки как новое представление либо обновляет выбранное. Колонка **Движение** показывает направление по распознанной операции; назначение доход/возврат/свои деньги уточняется независимо.
- **Открыть** у операции исправляет сумму, тип, категорию, назначение и свои поля. Исходное сообщение и история доступны отдельно.
- **CSV** выгружает отфильтрованные записи со своими колонками. **Подключение → Скачать резервную копию** включает исходные тексты, операции, историю, поля, представления и дашборды. Секреты подключения в экспорт не входят.

## Дашборды

Дашборды стоят первыми в меню и открываются по адресу `/`. Таблица имеет постоянную ссылку `/?tab=table`; ссылки из приложения продолжают открывать выбранный раздел.

В начале каждого дашборда показан график **Доходы и расходы во времени**. Выбери дни, недели (с понедельника) или месяцы и одну валюту. Флажки включают отдельные ряды; все поступления на карты показываются отдельным рядом и не считаются заработком. Столбец или список **Период** показывает точные суммы; **Операции периода** открывает таблицу с выбранными датами и валютой. При длинном диапазоне свыше 400 интервалов график переходит на месяцы с пояснением. Пропуски обозначают отсутствие загруженных записей, а не доказанный нулевой расход. Суммы считаются в целых минимальных единицах без потери точности; пересечения источников требуют сверки.

Первый дашборд содержит расходы, подтверждённые доходы, поступления на карты, категории, магазины и дни. **Новый дашборд** создаёт отдельную страницу. **Добавить виджет / Настроить** выбирает сумму расходов, подтверждённых доходов, поступлений, перемещений своих денег или количество, разрез, валюту и сохранённое представление. Разрезом может быть своя колонка. Валюты показываются отдельно. В доходах и расходах участвуют только учтённые записи.

**Поступления на карты** показывают распознанные зачисления с известными суммой, валютой и датой, включая записи на проверке: доходы, свои переводы, возвраты и внесение наличных. Виджет показывает количество записей с неуточнённым назначением. Исключённые записи и отмеченные возможные повторы в суммы не входят; пересечения источников нужно сверять. **Посмотреть поступления** открывает таблицу с фильтром по направлению. Если поступления нет в SMS и выписках, **Добавить доход** открывает форму ручной записи подтверждённого дохода; дата, сумма и источник заполняются владельцем.

Одновременно разные поля с телефона и ПК объединяются. Если одно поле исправлено по-разному, варианты доступны в **Разобрать конфликты**. Выбранный вариант возвращается на телефон при синхронизации. Устаревшая открытая веб-форма не перезаписывает новую запись.

## Заказы и чеки

Раздел **Заказы** содержит отдельную историю сервисов: дату с указанием её точности, сумму заказа, статус, позиции, способ оплаты и исходные документы. Импорт заказа не создаёт расход. Возможные совпадения с банковской записью предлагают связь; пользователь подтверждает её отдельно. Изменение связанного заказа или оплаты помечает связь для перепроверки. Баллы программы лояльности не считаются денежным доходом. Для каждого пакета указан охват: несколько сохранённых экранов нельзя считать полным архивом.

В истории есть фильтры **Еда / Такси**, дат и поиска. Итоги и помесячное сравнение используют суммы заказов из выбранной истории, отдельно для каждой валюты. Отменённые заказы сохраняются в списке, но исключаются из итогов и предложений связи с оплатой. Итоги истории не доказывают фактическое списание: оплату и возвраты проверяют по чекам и банку. Записи с неизвестной датой не получают вымышленный месяц; предположенный год отмечен. Эти суммы не складываются с банковскими расходами дашборда.

Подготовленный пакет формата `rhythm-service-orders-v1` из приватной `.samples/service-orders/` проверяется командой `node web/import-service-orders.mjs .samples/service-orders/yandex_go/captured-orders.json --preview`, затем `--apply` сохраняет копию базы и оригиналы. JSON должен быть настоящим сформированным пакетом; команда не читает закрытые базы приложений и сама не выгружает историю. Исходные документы сохраняются без изменений в `.web/order-files/`, проверяются по SHA-256 и доступны через авторизованный сервер. JSON-резервная копия включает сведения о заказах, связях и наблюдениях; сами PDF/снимки нужно сохранять вместе с папкой `.web/order-files/`.

## Где лежат данные

Общая база — `.web/money.sqlite`, журнал SQLite — соседние файлы WAL. Подключения и сессии хранятся в этой базе. Пароль для входа с другого браузера — `.web/admin-password.txt`. На самом ПК вход через `127.0.0.1` доступен локальному пользователю без ручного пароля. По сети финансовые API требуют вход или токен телефона. Сервер хранит хеши токенов; устройство можно отозвать через **Подключение**.

Папка `.web/` исключена из Git. Исходники публикуются отдельно от финансовых данных. Прежний дашборд в `personal-dashboard` использует свою базу и не изменён этим сервером.

Ручной запуск:

```powershell
node web/server.mjs
```

Нужен Node.js 24 или новее. Порт — 8788. При ручном запуске его меняет `FINANCE_PORT`, папку данных — `FINANCE_DATA_DIR`, объявляемый адрес — `FINANCE_HOST`; launcher использует стандартный порт. Автозапуск при входе в Windows не добавлен.

Проверки: `node --test tests/web.test.mjs`, `python tests/migration.py`, стандартный выпуск через `release.mjs`. API: `/api/events`, `/api/fields`, `/api/views`, `/api/dashboards`, `/api/sync`, `/api/backup`. Постоянная очередь телефона, версии записей и подтверждения пакетов защищают от повторной отправки.

Документация платформ: [SQLite в Node.js 24](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Android JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler), [Android WebView](https://developer.android.com/reference/android/webkit/WebView).
