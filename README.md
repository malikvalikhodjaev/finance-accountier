# My Personal Throughput Accounting — Android

Версия 0.7.8 добавляет личную подпись **МВ · Малик Валиходжаев**, знак потока и My в названии. В поступлениях доступен список типов: зарплата, проекты и клиенты, бизнес, подработка, другое. Поле своего текста открывается только для «Другое», дата выбирается календарём или кнопкой «Сегодня»; новые ручные поступления записываются без времени.

Локальный сборщик банковских SMS и push с аналитикой по категориям и продавцам. APK собран для Android 8.0 и новее. Разработан под присланный владельцем формат сообщений, а не под предположение о внутреннем API Uzum, Payme или Ipak Yuli.

Версия 0.7.7 добавляет [отдельные окна после оплаты, короткий ввод заработка и напоминания 5-го и 20-го](REMINDERS.md). По умолчанию вопросы повторяются каждые 10 минут с 09:00 до 20:00 по Ташкенту, пока не указан ответ или дата отсрочки. Ручной заработок сразу классифицируется для ТОС-дашборда при синхронизации.

Версия 0.7.4 открывает веб-дашборды первыми, добавляет график доходов/расходов по дням, неделям и месяцам, отдельный ряд всех поступлений и переход к операциям периода. История заказов/чеки дополняют банковские записи отдельными связями без удвоения расходов. Вопрос «На что?» поддерживает новые форматы исходящих SMS HUMO и UZCARD; исторический импорт вопросов не вызывает. Подробнее: [WEB.md](WEB.md).

Версия 0.3 добавляет [общие таблицы и дашборды на ПК и в приложении](WEB.md), свои колонки, сохранённые представления и двустороннюю синхронизацию по домашней сети. Веб-часть запускается через `Open-Finance.cmd`. Операции передаются после подключения к выбранному серверу.

Версия 0.5 добавляет [импорт PDF выписок Uzum Bank](BANK-IMPORT.md) с предварительным просмотром, сохранением оригинала, сверкой повторных выгрузок и отдельным разбором переводов/возвратов. В таблице на ПК и внутри приложения доступна кнопка «Импорт выписки».

Версия 0.6 принимает PDF через **«Поделиться → My Personal Throughput Accounting»**. Если домашний ПК недоступен, файл остаётся в «Полученных выписках» на телефоне. При доступном ПК открывается предпросмотр; операции добавляются только по кнопке пользователя. Незавершённую проверку можно продолжить без повторного выбора PDF.

Разработка, сохранение версий в GitHub и установка по Wi-Fi описаны в [DEVELOPMENT.md](DEVELOPMENT.md). Команда `node release.mjs` проводит проверки, создаёт коммит и тег, собирает подписанный APK и обновляет подключённый телефон. Версия и коммит видны внизу главного экрана. APK сохраняются в `output/`; первоначальные файлы 0.2.0 и 0.1 сохранены отдельно.

## После оплаты — «На что?»

1. Приходит банковское SMS или push об оплате поддержанного формата. Сборщик сначала сохраняет сумму, дату, магазин и исходное сообщение.
2. При разрешённом доступе поверх приложений открывается отдельное окно **На что потратил?** с суммой и продавцом; уведомление также доступно для ответа.
3. Нажми **Еда** или **Транспорт** для ответа одним нажатием. Через **Ответить** можно написать «обед», «продукты на неделю», «такси домой» или выбрать предложенный вариант прямо в уведомлении.
4. Нажатие на само уведомление открывает короткую карточку с категориями и полем ответа. **Позже** или смахивание уведомления оставляют операцию без назначения; ответ можно добавить в журнале.

Вопросы по новым распознанным покупкам включены по умолчанию, в том числе если категория продавца уже известна. Вопрос также показывается для неясного исходящего списания/P2P. Пополнения, снятие/внесение наличных, возможные повторы и исторический импорт не вызывают вопрос о расходе. Суммы распознанных покупок входят в учёт до ответа; неясное списание остаётся на разборе.

Текст ответа хранится в отдельном поле **purpose**, попадает в JSON-архив и в описание CSV. Короткие понятные ответы получают категорию по локальным правилам: например, «обед» → Еда, «такси домой» → Транспорт. Непонятные, смешанные и отрицательные формулировки сохраняются как текст без новой догадки о категории. Для неясного исходящего списания выбор расходной категории подтверждает расход, **Свои деньги** подтверждает перевод между своими счетами; свободный ответ без понятной категории сохраняется, а тип операции нужно уточнить отдельно.

Ответ относится к конкретной оплате и не меняет категорию всех будущих покупок у этого продавца. Это позволяет отличать такси и доставку, даже если в обоих SMS написано Yandex Go. Отдельная настройка **Категория продавца** по-прежнему задаёт правило для следующих покупок.

В Android уведомление может отображаться баннером или только в шторке — это зависит от настроек канала, режима «Не беспокоить» и MIUI. При выключенных уведомлениях операции продолжают сохраняться, а вопросы доступны в карточках.

## Начать на телефоне

1. Передай APK на телефон и установи. Если версия 0.1 уже установлена, устанавливай 0.2 поверх неё без удаления приложения: пакет и ключ подписи сохранены, база обновляется добавлением полей без удаления записей. Если Android попросит разрешить установку из выбранного приложения, разреши для этого источника.
2. Открой **My Personal Throughput Accounting → Выбрать Uzum, Payme и другие приложения**. Отметь именно банковские приложения, уведомления которых нужно учитывать.
3. Нажми **Дать доступ к уведомлениям** и включи доступ для **My Personal Throughput Accounting · сбор уведомлений**. Android предоставляет общий доступ к уведомлениям; код сборщика сохраняет только сообщения выбранных приложений.
4. Для прямого приёма новых SMS открой **SMS: задать отправителей**, впиши точные имена/номера банковских отправителей по одному на строку и дай запрошенное разрешение на получение SMS. Пустой список не принимает новые SMS. Для старой переписки открой **Импортировать старые SMS** и выбери банковских отправителей; подробнее в [HISTORY.md](HISTORY.md).
   Для вопросов включи уведомления **На что потратил?**. Если они запрещены, на главном экране появится кнопка **Разрешить вопросы после оплаты**; на Android 13 и новее она запрашивает разрешение POST_NOTIFICATIONS. В настройках сбора можно отдельно отключить вопросы, сохранив сбор операций.
5. Если это Xiaomi/MIUI, в настройках приложения включи автозапуск и разреши работу в фоне без ограничений батареи. Названия пунктов зависят от версии MIUI. Сбор фоновых сообщений нужно проверить на конкретном телефоне.
6. Проверь одну обычную оплату, поступление и перевод. Покупка должна появиться в расходах; неясный P2P или пополнение — в уточнениях. Неподдерживаемое сообщение останется в журнале для разбора.

Чтение старой переписки запрашивает READ_SMS при запуске импорта. RECEIVE_SMS и READ_SMS — ограниченные разрешения Android: возможность выдачи зависит от версии ОС и установщика APK. Если телефон не даёт их выдать, работоспособным источником могут остаться доступные push выбранных банков, а отдельные старые сообщения можно передать через «Поделиться».

## Если Play Protect блокирует установку

На телефоне владельца установка APK 0.2 из Telegram завершилась сообщением «Приложение не установлено». Владелец сообщил о предшествующем предупреждении Google о риске финансового мошенничества. Это соответствует [описанному Google механизму блокировки APK из интернет-источников](https://developers.google.com/android/play-protect/warning-dev-guidance): в манифесте приложения объявлены RECEIVE_SMS и сервис доступа к уведомлениям. Каждый из этих доступов может вызвать такую блокировку. Удаление только разрешения SMS не гарантирует установку версии, которая продолжает автоматически собирать push.

Для локальной проверки подготовлен путь установки через инструменты разработчика Android и USB. Он требует разрешённой пользователем USB-отладки. 8 октября 2026 установка 0.2.0 и первый запуск проверены на подключённом Redmi 14C с Android API 36 / HyperOS 3. Защита Play Protect и остальные системные ограничения скриптом не изменяются.

1. `node bootstrap-adb.mjs` скачивает стабильные Android SDK Platform Tools с сервера Google, проверяет размер и контрольную сумму по официальному описанию SDK, сохраняет источник в `.tools/adb/provenance.json`. Глобальная установка Android Studio не нужна.
2. Подключи телефон к компьютеру, включи USB-отладку в настройках разработчика и подтверди подключение именно этого компьютера на разблокированном телефоне. На подключённом Redmi есть отдельный переключатель **Установка через USB** с подписью «Разрешить установку приложений через USB»: его нужно временно включить в обычном профиле телефона, где находятся банковские приложения. Одного включения отладки недостаточно. После установки верни переключатель установки в исходное состояние.
   Не путай USB-отладку с отдельным **Режимом отладки** Xiaomi: на проверенном телефоне он создал временного пользователя 110 без банковских приложений и с ограничением `no_sms`. Штатный выход был доступен через одноимённое системное уведомление. Скрипт отказывается устанавливать APK в профиль с именем «Режим отладки» / «Debug mode». Разблокировка загрузчика ОС для установки не нужна.
3. `install-on-phone.ps1` — резервный запуск `node phone.mjs install --usb`: проверяет телефон и обычный профиль, устанавливает последнюю сборку текущего чистого Git-коммита поверх приложения и открывает его. Для выбора USB-устройства есть параметр `-DeviceSerial`. Обычные обновления идут через Wi-Fi по инструкции в DEVELOPMENT.md. Локальный сервер ADB использует порт 15037: стандартный 5037 на этом компьютере не разрешил привязку; 15037 проверен и работает. Настройки устройства сохраняются в локальном `.phone/device.json`.

8 октября 2026 первоначальные попытки вернули `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`. Это текст системного отказа; он сам по себе не доказывает, что владелец нажал «Отмена». После выхода из отдельного Режима отладки в обычный профиль 0 и включения **Установки через USB** именно в этом профиле ADB вернул `Success`, наличие пакета подтверждено `pm path`, запуск — `am start -W` со статусом `ok` и снимком главного экрана. Переключатель установки через USB затем выключен; приложение снова открыто. Вопросы после оплаты разрешены, выбрано 11 источников; при проверке главного экрана доступ к сбору уведомлений и прямой приём SMS ещё требовали настройки. Финансовые операции и работу в фоне эта проверка не подтверждает.

Чтобы устранить блокировку APK при распространении через интернет, Google предлагает проверить соответствие приложения правилам и при ошибочной блокировке подать обращение на пересмотр. Новая подпись, название приложения или повторная отправка APK сами по себе не подтверждают устранение причины.

## Что уже работает в коде

- Сбор выбранных push, приём новых SMS от точных разрешённых отправителей, приём текста через системное **Поделиться → My Personal Throughput Accounting**.
- SQLite внутри приложения. Для подключённой общей базы есть разрешение на сеть; до подключения серверу ничего не отправляется. Компьютер для локального сбора не нужен. Автоматическая Android-резервная копия отключена; экспорт и общая база описаны в WEB.md.
- Сохранение исходных текстов и отдельная история исправлений. Строгие признаки кода/пароля исключаются до сохранения. Это фильтр известных слов, а не гарантия распознавания любого будущего формата секретного сообщения.
- Парсер `Platezh`, `Pokupka`, `E-Com oplata`, `Spisanie c karty`, `Popolnenie scheta`, `Popolnenie nalichnimi v ATM`, `Vidacha nalichnykh v bankomate`, `Perevod na kartu` с полями `karta ***NNNN`, `summa`, `balans` и датой `DD.MM.YY HH:MM`.
- Покупки и E-Com оплаты учитываются автоматически. Яндекс Go имеет отдельную категорию «Яндекс Go»: текст не позволяет надёжно отличить такси от доставки. Неизвестные продавцы получают «Без категории»; назначение категории запоминается для следующих покупок у того же продавца.
- Неясные списания/P2P, пополнения счёта и платежи с указанным банковским посредником требуют уточнения: расход, доход или перевод своих денег. Они не включаются в суммы до решения. Пополнение не считается автоматически доходом.
- Снятие/внесение наличных — перемещение денег между картой и наличными. Если комиссия включена в сумму и не выделена в SMS, автоматически разделить её нельзя; для точной аналитики требуется ручная корректировка/отдельная запись комиссии.
- Повтор доставки того же события не создаёт новую запись. Совпадение полей банка в другой доставке помечается как возможный повтор и исключается из сумм до решения. Без ID банковской операции невозможно гарантированно отличить повтор от двух одинаковых оплат в одну минуту.
- Итоги за 7/30 дней и всю историю, категории и продавцы. Валюты учитываются отдельно. Неясные операции и возможные повторы видны отдельными счётчиками. Для возвратов отдельной автоматической обработки пока нет; соответствующие сообщения требуют разбора.
- Наличные и другие исключения вводятся вручную. Исключённые записи можно показать и восстановить; исходные сообщения не удаляются при исключении.

## Перенести в дашборд «Ритм»

Нажми **Экспорт операций · CSV**. Файл содержит только учтённые операции в существующем контракте:

`externalId,date,amount,currency,type,category,description`

Передай файл на компьютер. В «Ритме» открой финансовый импорт CSV, укажи постоянный источник **rhythm-phone**, проверь предпросмотр и импортируй. Повторный импорт того же файла использует прежние externalId. Если после первого импорта запись исправлена на телефоне, включая ответ на вопрос о назначении, дашборд отклонит отличающуюся строку с прежним ID: её нужно отдельно сверить и исправить в дашборде. Автоматической синхронизации исправлений в версии 0.2 нет.

**Резервная копия с исходными сообщениями · JSON** сохраняет исходный текст, распознанные поля и историю правок. JSON пока не импортируется обратно в приложение; это читаемый архив для сохранения данных. Экспорт может содержать личные финансовые сведения.

Файлы и данные существующего дашборда не изменяются сборщиком. Исторические банковские сообщения для локальных испытаний хранятся отдельно в `.samples/`, исключённой из Git. При передаче исторических сообщений на телефон нужно выбрать **Вся история**, чтобы увидеть их в аналитике.

## Проверка и сборка

Локальные инструменты скачиваются только с официальных серверов Microsoft и Google; архивы проверяются по контрольным суммам. Установка Android Studio и Gradle не нужна. Всё находится внутри отдельной папки проекта.

```powershell
node bootstrap-tools.mjs
node test.mjs
node --test tests/workflow.test.mjs
python tests/migration.py
node build.mjs
```

`test.mjs` проверяет парсер, точность сумм, отделение остатка, неясные переводы/поступления, сохранение неверных фрагментов для разбора, фильтр кодов, даты и CSV. APK проверяется `apksigner`, `zipalign` и `aapt2`. Это не заменяет проверку установки, интерфейса, разрешений и фона на реальном телефоне.

Проверено 7 октября 2026: **43 проверки парсера**, импорт в изолированное финансовое хранилище «Ритма», повторный импорт без удвоения и отклонение конфликтующей правки. Подпись APK v2/v3 и выравнивание проверены. 8 октября установка и первый запуск на реальном телефоне подтверждены; фоновый сбор и обработка реальной оплаты ещё не проверены. Личные приёмочные сценарии и проверка интеграции с отдельным дашбордом сохранены локально и исключены из публичного Git вместе с финансовыми образцами. Исходная документация и тесты сохранены без изменений в локальном архиве `output/source-0.2.0-before-public-git.zip`.

Версия 0.2 дополнительно проверяет правила вопроса/ответа: распознанные траты, неясные исходящие списания, исключение пополнений/наличных/повторов/исторического импорта, свободный ответ, перевод себе и описание CSV. SQL-миграция 1 → 2 проверяется против сохранённой схемы 0.1, включая сохранность исходных сообщений, сумм и истории правок. Ввод ответа через реальное Android-уведомление пока требует проверки на телефоне.

Ключ `.signing/local.jks` нужен для обновлений без удаления приложения. Сохраняй его отдельно от публичного Git. Сборка требует существующий ключ и не создаёт замену при его отсутствии. Это ключ локальной разработки со стандартным тестовым паролем; он не предназначен для публичного распространения в магазине.
